# Clear arrival26

Run **Run Arrival26.cmd**. This is an editable Unreal preview requiring the installed engine, not a packaged standalone game. The new map is `/Game/Airport26/L_Airport_Clarity26`. The warm foyer25 remains the visual base; this revision fixes first-time player navigation and viewport clarity.

The foyer now has one departure exit: **01 Check-in / Start here**, to the right. Its former direct left-hand corridor connection is a solid welcome wall, and the long privacy wall in the corridor has been removed. A numbered gold floor route leads through the offset passage to the check-in desk. Security instructions appear in the check-in room, where a blue route leads out through that room's north exit and turns left toward screening. Gate and boarding instructions become the current objective only after the earlier step is completed. Bag drop remains optional; carrying a suitcase after checking in makes it the next step.

A native-resolution journey card shows one current action. It renders after tonemapping and is independent of temporal history. A separate contextual prompt matches the aimed usable item, including check-in/bag drop while holding luggage. The information button and greeter provide a short direction response. E/click uses the aimed control; WASD/mouse moves/looks; Space stands; B shows the boarding pass; Tab toggles spectator. Check-in, bag acceptance, full screening traversal, gate validation and walking into the aircraft remain real gameplay state changes.

The project inherited `bAllowHighDPIInGameMode=False` from the engine. The project now explicitly enables it. The comparison helper also exposed an actual888×500 viewport despite1600×1000 launch arguments; the runtime now applies the requested client resolution after the viewport exists. The normal launcher requests1920×1080, and proof helpers request1600×1000. The live `ClaritySession26.json` records the actual viewport and rendering values. The final profile uses TAA4 samples, current-frame weight0.30, filter size0.70, screen percentage100, sharpening0, motion blur0 and DOF0. This keeps smoother edges than the spatial option while shortening history. Rendering remains map-scoped except the necessary high-DPI application setting. The previous engine config is preserved in `SourceAssets/RecoveryBefore26`.

The rendering study compared the original TAA settings, native FXAA,115% FXAA and the shorter-history TAA profile using actual viewport `Shot` captures during a repeatable pan. Reports include actual dimensions and brief frame timing samples. They are short comparisons, not a sustained FPS guarantee. The initial low-resolution comparison is retained under `ArtBible/Diagnostics/InitialViewport`. See Epic's [anti-aliasing documentation](https://dev.epicgames.com/documentation/unreal-engine/anti-aliasing-and-upscaling-in-unreal-engine) for the distinction between temporal and spatial methods. Local engine source `SlateApplication.cpp`, `BaseEngine.ini` and `GameViewportClient.cpp` were checked for DPI and screenshot behaviour.

`Airport_Clarity26.blend` is the editable placed scene and new asset library. `Exports/airport_layout.json` contains the exact route, portals, interactions and placements. Five new mesh families replace the sign/details, information, transition and floor variants and add the closed shortcut/route system. Existing seating, portal, canopy, aircraft and character meshes are preserved. Signs use locally installed Segoe semibold/bold outlines; the tiny high-frequency entrance-mat ribs were replaced by30 broader channels. System font files are referenced locally and are not bundled for redistribution. Source HUD cards and hints are generated with Pillow and remain editable in `SourceAssets/hud26.py`.

Build in order: Blender background with `SourceAssets/model_clarity26.py`; Python `SourceAssets/hud26.py`; Unreal's Python commandlet on `SourceAssets/build_clarity26_unreal.py`. `SourceAssets/finalize26.py` serializes this build, the focused passenger-route verification and native photographs. `run26.py compare` performs the rendering study; `run26.py qa` verifies the process; `run26.py photos` captures room views and the first-person arrival; `make_review26.py` checks hashes and generates the review. Do not run multiple heavy engine instances concurrently.

`ArrivalQA26.json` records a continuous route from arrival to the actual parked aircraft, including the optional physical bag drop and correct next-step/interaction prompts. It does not spend time checking every passenger, shop or cabinet. Gameplay and review images are actual viewport captures, with hashes. The warm art direction remains for the user to review; other airport rooms, characters and exterior landscaping are not certified finished by these functional checks. Original Rooms24, Foyer25 and aircraft sources remain separate. No paid assets or generation were used in this revision.
