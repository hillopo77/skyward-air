# Airside38 implementation and acceptance

Implemented in this folder only. The shared master and live editors were not altered by this fixer. The root integration run applies the changes to the saved master and native map.

## Integration

1. Source: import `airside38`, call `plan(ctx)` during the planning phase and `build(ctx)` during the asset phase. Both are implemented against `Fixes/CONTRACT.md`.
2. Native: call `airside38.apply_native(ctx)` after all new actors and architecture have been placed. It shifts aircraft roots, remounts L1's misplaced collision proxy, makes the articulated bridge movable and asserts a complete scenery clearance result.
3. Copy `airport_airside38.py` **and** `airside_math38.py` into Content/Python. After `plane18_runtime.install(P)` and before `P.configure/P.start`, call `airport_airside38.prepare_plane(P,D)`. Add airport floors only afterwards.
4. After airport initialization, call `airport_airside38.install(G)`. Keep every name in `D.aircraft38.bridge.moving_names` as a separate StaticMeshActor. All enclosing geometry, seals, rails and lights move with these actors.
5. Journey/nav integration consumes `D.aircraft38`. L1 is `P.STATE['movables']['Aircraft door 1L']`, using `progress` and `target` with closed tolerance .015. The new source doorway crossing is **x=14.1**, inside rect `[14.1,18.4,-.3,2.0]`; start aboard is `[15.2,.675,1.62]`. The fixed terminal portal remains `[-14,.675]`.
6. Use `G.airside38['floor_enabled']()` for the bridge polygon floors. Do not retain the old long bridge rectangle. Use `request_bridge`, `can_depart`, or `guard_departure(callback)` for bridge/flight actions. No airport flight controller is fabricated by this module.
7. Bridge practical light records include `name`, `position`, `watts`, `follow_actor` and `local_point`. Rendering may attach them to the indicated sleeve; runtime also follows correctly named lights during articulation.

- `test_airside38.py`: eight real-manifest, geometry and interlock tests; checks all absolute record families, nested roller closed positions/kinematic starts, layout inspection/seat paths, unchanged deltas/basis/dimensions, idempotence, untouched coordinate conversion, continuous collision sweep, bounded route floors, full stow, wheel contacts and unsafe departure refusal.

The isolated `.blend` contains the editable new bridge/service assets and empty aircraft linkage fixtures, not the complete aircraft. The complete saved aircraft remains in the root's preserved source master. No in-game success or final visual approval is claimed from these unit tests. Native docking, door sweep, articulation, final source/native label placement, whole-scene sweep, lighting and tug operation require the root's integration run and genuine screenshots.
